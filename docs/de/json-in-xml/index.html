JSON in XML umwandeln

Wählen Sie eine JSON-Datei aus oder fügen Sie JSON ein. Sie erhalten eingerücktes, wohlgeformtes XML. Die Zuordnung ist dieselbe wie im Tool „XML in JSON“, Sie können also in beide Richtungen umwandeln.

Ihre Datei bleibt auf Ihrem Gerät: Die Umwandlung läuft in Ihrem Browser, und nichts wird hochgeladen.

    So gehen Sie vor

    1. Wählen Sie eine JSON-Datei aus, ziehen Sie sie auf das Feld oder fügen Sie JSON ein. Klicken Sie dann auf „Umwandeln“.
    2. Legen Sie den Namen des Wurzelelements, den Namen für Einträge verschachtelter Listen und die Einrückung fest, und entscheiden Sie, ob die XML-Deklaration hinzugefügt wird.
    3. Lesen Sie die Hinweise unter dem Ergebnis: Sie nennen umbenannte Schlüssel und andere Änderungen.
    4. Laden Sie die .xml-Datei herunter oder kopieren Sie das Ergebnis.

    So funktioniert die Umwandlung

    Zuordnung zwischen XML und JSON

    • Jedes Element wird zu einem Schlüssel mit dem Namen des Elements. Namensraum-Präfixe bleiben Teil des Namens: soap:Body.
    • Attribute werden zu Schlüsseln mit vorangestelltem „@“: id="7" wird zu "@id": "7". Namensraum-Deklarationen bleiben auf dieselbe Weise erhalten, als "@xmlns:soap".
    • Ein Element, das nur Text enthält, wird zu diesem Text. Hat es zusätzlich Attribute oder Kindelemente, steht sein Text unter "#text": Aus <price currency="EUR">12.50</price> wird {"price": {"@currency": "EUR", "#text": "12.50"}}.
    • Elemente, die sich unter demselben Elternelement wiederholen, werden zu einem Array, in der Reihenfolge des Dokuments. Abwechselnde Namen werden gruppiert; die Reihenfolge zwischen verschiedenen Namen bleibt also nicht erhalten.
    • CDATA-Abschnitte werden zu normalem Text. Kommentare, Verarbeitungsanweisungen und die DOCTYPE-Deklaration entfallen. Entitäten, die nur in einer externen DTD definiert sind, etwa &nbsp; in XHTML, bleiben so stehen, wie sie geschrieben sind; ein Hinweis weist darauf hin.
    • Ein leeres Element wie <note/> wird zu "". Leerraum zwischen Elementen entfällt, und am Anfang und Ende von Text wird Leerraum entfernt, außer innerhalb von xml:space="preserve".
    • Alle Werte bleiben Zeichenketten, weil XML keine Datentypen kennt: "00123" behält seine führenden Nullen.

    Von JSON zu XML

    • Ein Objekt mit genau einem Schlüssel (dessen Wert kein Array ist) ergibt das Wurzelelement. Alles andere wird in das Wurzelelement eingeschlossen, dessen Name in den Optionen steht.
    • Schlüssel, die mit „@“ beginnen, werden zu Attributen, "#text" wird zum Text des Elements.
    • Ein Array wird zu wiederholten Elementen mit dem Namen des Schlüssels. Arrays in Arrays werden eingeschlossen, und ihre Einträge erhalten den Namen aus der Option „Name für Listeneinträge“.
    • null und "" werden zu einem leeren Element, zum Beispiel <note/>. Ein leeres Array erzeugt kein Element.
    • Schlüssel, die keine gültigen XML-Namen sind, werden angepasst: Ungültige Zeichen werden zu „_“, und ein Name, der mit einer Ziffer beginnt, erhält ein „_“ davor.

    Fragen und Antworten

    Welches Element wird zum Wurzelelement?

    Ist das JSON ein Objekt mit genau einem Schlüssel, dessen Wert kein Array ist, wird dieser Schlüssel zum Wurzelelement. Sonst wird der Inhalt in ein Wurzelelement mit dem Namen aus den Optionen eingeschlossen, standardmäßig „root“.

    Wie erzeuge ich Attribute?

    Beginnen Sie den Schlüssel mit „@“, und verwenden Sie "#text" für den Text des Elements: {"price": {"@currency": "EUR", "#text": "9.90"}} ergibt <price currency="EUR">9.90</price>.

    Was passiert mit Arrays, null und leeren Zeichenketten?

    Ein Array wird zu einem Element pro Eintrag, jeweils mit dem Namen des Schlüssels. Arrays in Arrays werden in ein Element eingeschlossen, dessen Einträge „item“ heißen (den Namen können Sie ändern). null und "" werden zu einem leeren Element wie <note/>. Ein leeres Array erzeugt kein Element.

    Was passiert, wenn ein Schlüssel kein gültiger XML-Name ist?

    Zeichen, die in XML-Namen nicht vorkommen dürfen, werden durch „_“ ersetzt, und ein Name, der mit einer Ziffer beginnt, erhält ein „_“ davor: Aus „first name“ wird first_name, aus „1st“ wird _1st. Die Hinweise unter dem Ergebnis nennen die umbenannten Schlüssel.

    Welche Zeichen werden maskiert?

    &, < und > im Text sowie &, <, " und außerdem Tabulatoren und Zeilenumbrüche in Attributwerten. Steuerzeichen, die XML 1.0 nicht erlaubt, etwa U+0001, stoppen die Umwandlung; die Meldung nennt den Pfad des Werts.
