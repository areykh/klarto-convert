XML in JSON umwandeln

Wählen Sie eine XML-Datei aus oder fügen Sie XML ein. Sie erhalten JSON nach einer dokumentierten, umkehrbaren Zuordnung. Fehler im XML werden mit Zeile und Spalte angezeigt.

Ihre Datei bleibt auf Ihrem Gerät: Die Umwandlung läuft in Ihrem Browser, und nichts wird hochgeladen.

    So gehen Sie vor

    1. Wählen Sie eine XML-Datei aus, ziehen Sie sie auf das Feld oder fügen Sie XML in das Textfeld ein. Klicken Sie dann auf „Umwandeln“.
    2. Prüfen Sie die Optionen: ob wiederholte Elemente überall zu Arrays werden, welche Elemente immer Arrays sein sollen und wie weit eingerückt wird.
    3. Sehen Sie sich die Vorschau an. Laden Sie dann die .json-Datei herunter oder kopieren Sie das Ergebnis.
    4. Enthält das XML einen Fehler, nennt die Meldung Zeile und Spalte. Beheben Sie ihn und wandeln Sie erneut um.

    So funktioniert die Umwandlung

    Zuordnung zwischen XML und JSON

    • Jedes Element wird zu einem Schlüssel mit dem Namen des Elements. Namensraum-Präfixe bleiben Teil des Namens: soap:Body.
    • Attribute werden zu Schlüsseln mit vorangestelltem „@“: id="7" wird zu "@id": "7". Namensraum-Deklarationen bleiben auf dieselbe Weise erhalten, als "@xmlns:soap".
    • Ein Element, das nur Text enthält, wird zu diesem Text. Hat es zusätzlich Attribute oder Kindelemente, steht sein Text unter "#text": Aus <price currency="EUR">12.50</price> wird {"price": {"@currency": "EUR", "#text": "12.50"}}.
    • Elemente, die sich unter demselben Elternelement wiederholen, werden zu einem Array, in der Reihenfolge des Dokuments. Abwechselnde Namen werden gruppiert; die Reihenfolge zwischen verschiedenen Namen bleibt also nicht erhalten.
    • CDATA-Abschnitte werden zu normalem Text. Kommentare, Verarbeitungsanweisungen und die DOCTYPE-Deklaration entfallen. Entitäten, die nur in einer externen DTD definiert sind, etwa &nbsp; in XHTML, bleiben so stehen, wie sie geschrieben sind; ein Hinweis weist darauf hin.
    • Ein leeres Element wie <note/> wird zu "". Leerraum zwischen Elementen entfällt, und am Anfang und Ende von Text wird Leerraum entfernt, außer innerhalb von xml:space="preserve".
    • Alle Werte bleiben Zeichenketten, weil XML keine Datentypen kennt: "00123" behält seine führenden Nullen.

    Fragen und Antworten

    Wie werden Attribute und Text im JSON gespeichert?

    Jedes Attribut wird zu einem Schlüssel mit „@“ vor seinem Namen; aus id="7" wird also "@id": "7". Ein Element, das nur Text enthält, wird zu diesem Text. Hat das Element zusätzlich Attribute oder Kindelemente, steht der Text unter "#text".

    Warum stehen alle Zahlen in Anführungszeichen?

    XML kennt keine Datentypen, daher wird jeder Wert als Zeichenkette übernommen. Würde man "00123" oder "1e5" in Zahlen umwandeln, würden sich die Daten ändern. Wandeln Sie die Typen in Ihrem eigenen Code um, wo Sie wissen, welche Felder Zahlen sind.

    Wann wird ein Element zu einem Array?

    Wenn es unter demselben Elternelement mehr als einmal vorkommt. Ist „Wiederholte Elemente überall als Array“ eingeschaltet (Standard), wird ein Element, das sich irgendwo wiederholt, in jedem Datensatz am selben Pfad zu einem Array. So haben alle Datensätze dieselbe Form. Elemente, die sich in dieser Datei nie wiederholen, tragen Sie unter „Immer als Array“ ein.

    Was passiert mit Namensräumen, Kommentaren und CDATA?

    Präfixe bleiben in den Namen erhalten, etwa "soap:Body", und Namensraum-Deklarationen bleiben als "@xmlns"-Schlüssel erhalten. So liefert „JSON in XML“ dieselben Namensräume zurück. CDATA-Abschnitte werden zu normalem Text. Kommentare und Verarbeitungsanweisungen entfallen.
