XML-Validator: Wohlgeformtheit prüfen

Wählen Sie eine XML-Datei aus oder fügen Sie XML ein, um zu prüfen, ob es wohlgeformt ist. Wenn nicht, sehen Sie den ersten Fehler mit Zeile, Spalte und einer Markierung im Text.

Ihre Datei bleibt auf Ihrem Gerät: Die Umwandlung läuft in Ihrem Browser, und nichts wird hochgeladen.

    So gehen Sie vor

    1. Wählen Sie eine XML-Datei aus, ziehen Sie sie auf das Feld oder fügen Sie XML ein. Klicken Sie dann auf „Prüfen“.
    2. Lesen Sie das Ergebnis: „Wohlgeformtes XML“ mit einer kurzen Zusammenfassung oder den ersten Fehler mit Zeile und Spalte.
    3. Beheben Sie den Fehler an der markierten Stelle und prüfen Sie erneut, bis das Dokument wohlgeformt ist.

    So funktioniert die Umwandlung

    Was geprüft wird

    • Die Wohlgeformtheit nach XML 1.0 und Namespaces in XML 1.0: ein Wurzelelement, passende und korrekt verschachtelte Tags, Attribute in Anführungszeichen und ohne Doppelungen, gültige Namen und Zeichen, definierte Entitäten, deklarierte Namensraum-Präfixe.
    • Die Prüfung stoppt beim ersten Fehler und zeigt seine Zeile und Spalte mit dem umgebenden Text.
    • Das Dokument wird nicht gegen eine DTD oder ein XML-Schema (XSD) validiert. Externe Dateien werden nie geladen; Entitäten, die nur dort definiert sind, etwa &nbsp; in XHTML, werden in einem Hinweis aufgeführt.

    Fragen und Antworten

    Was genau wird geprüft?

    Die Wohlgeformtheit nach XML 1.0 und Namespaces in XML 1.0: ein Wurzelelement, korrekt verschachtelte und passende Tags, Attribute in Anführungszeichen und ohne Doppelungen, gültige Namen und Zeichen, definierte Entitäten und deklarierte Namensraum-Präfixe.

    Wird gegen ein XSD-Schema oder eine DTD validiert?

    Nein. Ein wohlgeformtes Dokument kann trotzdem gegen sein Schema verstoßen. Der Validator liest eine DOCTYPE-Deklaration und ihre internen Entitätsdeklarationen, prüft das Dokument aber nicht gegen die DTD und lädt nie externe Dateien.

    Welche Fehler sind am häufigsten?

    Ein nicht maskiertes & im Text (schreiben Sie &amp;), ein schließendes Tag, das nicht zum offenen Element passt, ein zweites Element nach dem Ende des Wurzelelements sowie Leerzeilen oder Leerzeichen vor der Deklaration <?xml …?>.

    Wie werden Zeilen und Spalten gezählt?

    Zeilen und Spalten beginnen bei 1. CRLF, LF und CR beenden jeweils eine Zeile, und jedes Zeichen (Unicode-Codepunkt) zählt als eine Spalte. Angegeben wird die Stelle, an der das Problem erkannt wurde: Bei einem Element, das nie geschlossen wird, ist das das Ende der Datei, und die Meldung nennt die Zeile, in der das Element geöffnet wurde.
