XML validator: check well-formedness

Choose an XML file or paste XML to find out whether it is well-formed. If it is not, you see the first error with its line, column and a marker in the text.

Your file stays on your device: the conversion runs in your browser and nothing is uploaded.

    How to use it

    1. Choose an XML file, drop it on the box, or paste XML and press Check.
    2. Read the result: “Well-formed XML” with a short summary, or the first error with its line and column.
    3. Fix the error at the marked position and check again until the document is well-formed.

    How the conversion works

    What is checked

    • Well-formedness as defined by XML 1.0 and Namespaces in XML 1.0: one root element, matching and properly nested tags, quoted and unique attributes, valid names and characters, defined entities, declared namespace prefixes.
    • The check stops at the first error and shows its line and column with the text around it.
    • The document is not validated against a DTD or an XML Schema (XSD). External files are never loaded; entities defined only there, such as &nbsp; in XHTML, are listed in a note.

    Questions and answers

    What exactly is checked?

    Well-formedness as defined by XML 1.0 and Namespaces in XML 1.0: one root element, properly nested and matching tags, quoted and unique attributes, valid names and characters, defined entities and declared namespace prefixes.

    Does it validate against an XSD schema or a DTD?

    No. A well-formed document can still break its schema. The validator reads a DOCTYPE and its internal entity declarations, but it does not check the document against the DTD and never loads external files.

    Which errors are most common?

    An unescaped & in text (write &amp;), a closing tag that does not match the open element, a second element after the root element has ended, and blank lines or spaces before the <?xml …?> declaration.

    How are lines and columns counted?

    Lines and columns start at 1. CRLF, LF and CR each end a line, and every character (Unicode code point) counts as one column. The position is where the problem was detected: for an element that is never closed, that is the end of the file, and the message names the line where the element was opened.
