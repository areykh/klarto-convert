Convertir JSON a XML

Elija un archivo JSON o pegue JSON para obtener XML bien formado y con sangría. La correspondencia es la misma que en la herramienta XML a JSON, así que puede convertir en ambos sentidos.

Su archivo no sale de su dispositivo: la conversión se realiza en su navegador y no se sube nada.

Opciones

    Cómo se usa

    1. Elija un archivo JSON, arrástrelo al recuadro o pegue el JSON y pulse Convertir.
    2. Indique el nombre del elemento raíz, el nombre de los elementos de las listas anidadas, la sangría y si se incluye la declaración XML.
    3. Lea las notas bajo el resultado: indican las claves renombradas y otros cambios.
    4. Descargue el archivo .xml o copie el resultado.

    Cómo funciona la conversión

    Correspondencia entre XML y JSON

    • Cada elemento se convierte en una clave con el nombre del elemento. Los prefijos de espacio de nombres forman parte del nombre: soap:Body.
    • Los atributos se convierten en claves con una «@» delante: id="7" se convierte en "@id": "7". Las declaraciones de espacio de nombres se conservan de la misma forma, como "@xmlns:soap".
    • Un elemento que solo contiene texto se convierte en ese texto. Si además tiene atributos o elementos hijos, su texto va en "#text": <price currency="EUR">12.50</price> se convierte en {"price": {"@currency": "EUR", "#text": "12.50"}}.
    • Los elementos que se repiten bajo el mismo padre se convierten en un array, en el orden del documento. Los nombres intercalados se agrupan, así que no se conserva el orden entre elementos de nombres distintos.
    • Las secciones CDATA se convierten en texto normal. Los comentarios, las instrucciones de procesamiento y el DOCTYPE se descartan. Las entidades definidas solo en una DTD externa, como &nbsp; en XHTML, se conservan tal como están escritas, con una nota.
    • Un elemento vacío como <note/> se convierte en "". Los espacios en blanco entre elementos se descartan, y se quitan los espacios al principio y al final del texto, salvo dentro de xml:space="preserve".
    • Todos los valores siguen siendo cadenas, porque XML no tiene tipos de datos: "00123" conserva sus ceros a la izquierda.

    De JSON a XML

    • Un objeto con exactamente una clave (cuyo valor no es un array) da el elemento raíz. Cualquier otro contenido se envuelve en el elemento raíz indicado en las opciones.
    • Las claves que empiezan por «@» se convierten en atributos, y "#text", en el texto del elemento.
    • Un array se convierte en elementos repetidos con el nombre de la clave. Los arrays dentro de arrays se envuelven, y sus valores reciben el nombre indicado en la opción «Nombre de los elementos de lista».
    • null y "" se convierten en un elemento vacío, por ejemplo <note/>. Un array vacío no produce ningún elemento.
    • Las claves que no son nombres XML válidos se ajustan: los caracteres no válidos se sustituyen por «_», y un nombre que empieza por un dígito recibe un «_» delante.

    Preguntas y respuestas

    ¿Qué elemento pasa a ser la raíz?

    Si el JSON es un objeto con exactamente una clave cuyo valor no es un array, esa clave pasa a ser el elemento raíz. Si no, el contenido se envuelve en un elemento raíz con el nombre indicado en las opciones, «root» de forma predeterminada.

    ¿Cómo creo atributos?

    Empiece la clave con «@» y use "#text" para el texto del elemento: {"price": {"@currency": "EUR", "#text": "9.90"}} da <price currency="EUR">9.90</price>.

    ¿Qué pasa con los arrays, null y las cadenas vacías?

    Un array se convierte en un elemento por cada valor, cada uno con el nombre de la clave. Los arrays dentro de arrays se envuelven en un elemento cuyos valores se llaman «item» (puede cambiar el nombre). null y "" se convierten en un elemento vacío como <note/>. Un array vacío no produce ningún elemento.

    ¿Y si una clave no es un nombre XML válido?

    Los caracteres que no pueden aparecer en un nombre XML se sustituyen por «_», y un nombre que empieza por un dígito recibe un «_» delante: «first name» pasa a ser first_name, y «1st», _1st. Las notas bajo el resultado indican las claves renombradas.

    ¿Qué caracteres se escapan?

    &, < y > en el texto, y &, <, " además de tabuladores y saltos de línea en los valores de atributo. Los caracteres de control que XML 1.0 no permite, como U+0001, detienen la conversión, y el mensaje indica la ruta del valor.
